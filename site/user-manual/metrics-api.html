    vLLM Engine Metrics API Reference

    The vLLM engine exposes real-time performance and health metrics via an OpenAI-compatible Prometheus endpoint. These metrics are used by the cmc llm monitor llm command and the full observability stack (Prometheus/Grafana).

    Accessing the Metrics Endpoint

    By default, the metrics are available at the /metrics endpoint of your vLLM server.

    # Using curl to view raw metrics (replace <port> with your tunneled port)
curl http://localhost:<port>/metrics

    Key Metrics Reference

    The following metrics are the most critical for monitoring the health and efficiency of your model deployment.

    1. Throughput & Performance

    • vllm:prompt_tokens_total: Total number of prompt tokens processed. Used to calculate request volume.
    • vllm:generation_tokens_total: Total number of tokens generated by the model.
    • Throughput (TPS): Calculated as (generation_tokens_total) / time.

    2. Resource Utilization

    • vllm:gpu_kv_cache_usage_per cent: The percentage of the pre-allocated GPU KV cache currently in use.
    • High (>90%): Indicates the server is near its capacity for concurrent requests.
    • Low (<20%): Suggests the server is underutilized or the gpu_memory_utilization is set too high for the current load.
    • vllm:gpu_cache_usage_per cent: Overall GPU memory usage for the cache.

    3. Request Queue Management

    • vllm:num_requests_running: The number of requests currently being processed by the GPU engine.
    • vllm:num_requests_swapped: The number of requests that have been swapped from GPU VRAM to CPU RAM due to memory pressure.
    • Warning: High swap rates significantly increase latency. If this value is consistently above 0, consider reducing max_num_seqs or increasing available VRAM.
    • vllm:num_requests_waiting: The number of requests waiting in the queue to be processed.

    Integration with Monitoring Tools

    Terminal Monitoring

    The cmc llm monitor llm command polls this API every second (by default) and presents the data in a human-readable dashboard.

    Prometheus/Grafana

    The observability stack uses a Prometheus scraper to collect these metrics over time, allowing you to visualize: - Token Throughput Spikes: Identify peak usage times. - VRAM Pressure: Correlation between request volume and KV cache usage. - Latency Trends: Monitoring the impact of swapping on response times.
